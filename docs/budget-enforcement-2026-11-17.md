# 请求级预算控制部署与验证（2026-11-17）

## 已部署行为

服务器 179.214.2.3 已应用 `0035_budget_requests`。API、planning-execution、result 与独立私有预算代理使用同一发布镜像。预算账户 `full-acceptance-20261117` 已启用：总额 250 元，测评 240 元、分析 10 元；仅允许 DeepSeek-V4.1-Flash-1017 的 GPQA 198 题、AutomationBench 600 题，两个数据集请求并发各不超过 24。分析限同任务完成后的已启动分析作业，单次输出最多 4096 tokens，并发 1。

- 请求前通过 PostgreSQL 账户行锁预留上界费用，提交成功后才连接上游；各数据集共享测评分项额度。预留占满时等待已发送请求结算，不抢占额度、不偷偷降低模型参数。
- 使用官方最高档价格、完整上下文输入上界及请求输出上限预留；结算以已返回输入/输出用量按官方未缓存高峰价保守记账。保留价格版本、来源哈希及 token 上界。`spent_upper_bound` 是官方价格口径的费用上界，不是服务商实际账单；缓存优惠不用于提前放宽额度。GLM 自定义网关实际收费差异尚未核验。
- 相同任务、数据集、请求内容使用稳定哈希去重；重复请求被拒绝，不自动再次调用模型。重复结算幂等；结果未知、缺失用量或中断不补零、不释放预留，并阻断后续请求。
- 代理重启时将未结清请求标记待查证并阻断账户。异常账务错误使代理停止放行，须恢复查证；不通过重启自动重测。
- 流式响应实时转发，捕获最后的用量；账务提交完成前不发送最终 DONE。缺失用量时中断流并保留预留，不伪造完成。客户端断开时终止代理侧等待，未知结果保守保留。
- 任务提交与独立预算一对一绑定，冻结预算 ID、分项额度和截止时间；任务启动后不能另建任务共用该额度。到截止时间停止新请求，并由任务工作进程请求取消，沿用原进程查证和清理机制。
- API 和执行 Worker 必须读取同一受保护路由配置；配置缺失、模型/任务范围不匹配时阻断，不回退直连。凭据仍由后台保管，执行容器只拿到有范围和期限的代理票据；快照和导出不含票据，日志及原生产物检查使用对应票据脱敏。
- 启用该预算模式时，旧版直接测评提交和付费吞吐探测入口返回 409；历史查询、取消及清理保留，统一测评任务入口继续使用。分析调用同样经过预算代理。

新增 `GET /api/autoeval/v1/evaluation-tasks/{run_id}/budget`，返回额度、预留、费用上界、状态、截止时间和待查证请求数；历史任务没有冻结预算时返回 `not_configured`。此次没有改动前端表单，也没有发布其他未提交的前端改动。

## 恢复约定

遇到账户 blocked 或待查证请求时，先核对上游请求及用量，保留账本和预留；不得清零、解除绑定或自动重测。需要回滚时先停止新提交，确认已发请求及远程进程状态，再停止代理和对应 Worker；不能把正在运行的任务回退到不经过预算的旧执行器。保留数据库备份、部署配置和证据。
