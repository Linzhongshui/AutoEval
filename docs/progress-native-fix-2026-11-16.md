# 样本进度与模型输入输出修复

## 原因

统一任务的执行桥接只写出 `tool_running`，未采集逐题计数；已有原生输入输出补充逻辑仅识别旧 `aisbench_cli_monitor` 路径和 `cli-native-v1` 归档，统一任务因此显示占位文字。

## 修复

- 独立运行副本每两秒观察本作业目录下、指定模型和数据集的原生预测记录。总数及样本身份来自冻结清单；按样本唯一计数，记录缺口、半写入记录、临时/最终文件重复均不会被算成更多完成样本。执行完成数与评分正确数分开。
- 通过现有 SSH 控制链路读取观测，写入对应数据集的监控绑定；记录来源 `aisbench_native_predictions`、采集时间、真实适配器进程及最终快照。过期、跨任务观测、计数倒退或记录冲突保留最后可靠值，不重启模型。
- 执行结束前，原生预测文件按作业归档到对象存储，保存哈希和冻结的工具 case ID → 平台样本 ID 映射。Case 接口读取时分别校验原执行证据和原生归档，再返回输入、响应和来源引用；不改写原报告、评分或旧 case 哈希。
- 已结束且从未采集监控的任务，从已归档的逐样本执行记录展示完成比例，来源为 `archived_case_executions`。该汇总不会伪装成过去的实时监控快照。
- 抽屉区分“未采集”和真正的空字符串；长输入输出自动换行。
